## 1. システムの目的

来訪者の事前登録から入退室記録までを一元管理し、受付業務の効率化とセキュリティ強化を図る。

## 4. データベース設計

### テーブル: `visits`

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | 主キー（自動生成） |
| company_name | text | 来訪者の会社名 |
| representative_name | text | 代表来訪者名 |
| visitor_count | integer | 来訪者人数（1以上） |
| staff_name | text | 当社担当者名 |
| staff_user_id | uuid | 登録スタッフのユーザーID |
| scheduled_date | date | 来訪予定日 |
| entry_time | timestamptz | 入室時刻 |
| exit_time | timestamptz | 退室時刻 |
| notes | text | 備考 |
| status | text | ステータス（後述） |
| created_at | timestamptz | 作成日時 |
| updated_at | timestamptz | 更新日時（自動更新） |

### ステータス定義

| 値 | 表示名 | 説明 |
|---|---|---|
| `scheduled` | 予定 | 事前登録済み・来訪前 |
| `checked_in` | 入室中 | 入室記録済み |
| `completed` | 完了 | 退室記録済み |
| `cancelled` | キャンセル | キャンセル済み |

## 5. セキュリティ設計

### 認証方式
- Supabase Auth によるメール＋パスワード認証
- スタッフアカウントは管理者が招待制で作成（自己登録不可）

### アクセス制御（Row Level Security）

| 操作 | 認証済みスタッフ | キオスク（未認証） |
|---|---|---|
| 全件読取 | ○ | × |
| 来訪登録 | ○（自分の登録のみ） | × |
| 来訪更新 | ○（自分の登録のみ） | △（入退室時刻のみ） |

### キオスクのセキュリティ
- `/kiosk` 画面は認証不要（iPadで手軽に操作するため）
- 入退室時刻の更新はサーバーサイドのAPI Route（`/api/visits/[id]/checkin`）が Service Role Key を使用して処理
- Service Role Key はサーバー側のみで使用し、ブラウザには公開しない

---

## 6. 運用設計

### iPad設定
- Safari のホームページを `/kiosk` に設定
- iOS ガイドアクセス（設定 > アクセシビリティ > ガイドアクセス）でキオスク URL にロックし、他アプリへの誤操作を防止

### スタッフアカウント管理
- Supabase ダッシュボード > Authentication > Users > Invite User からメールアドレスで招待
- パスワードは招待メールから各自設定
